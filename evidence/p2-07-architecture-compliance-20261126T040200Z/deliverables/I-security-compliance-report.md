## 2. Security Audit Deep-Dive & Remaining PoC Security Limitations (`G1 – G8`)

1. **Human Review Identity (`Disclosed PoC Limitation`):** Default CLI/TUI operator identity (`--reviewer-ref`) operates in `POC_CALLER_ASSERTED_UNAUTHENTICATED` mode (though `AuthorizedReviewManager` supports `require_authenticated_context=True` and `reviewer_directory` checks). Enterprise SSO/OIDC + RBAC is required under `CAP-05` Pillar 2.
2. **Audit Persistence Crash Micro-Window (`Disclosed PoC Limitation`):** JSONL audit chains use single-host file locking; an OS `SIGKILL` between JSONL append and SQLite commit is detectable via `reconcile_review_audit()`. Centralized transactional/WORM audit storage is required for production (`CAP-05`).
3. **Container & Host Hardening (`Disclosed PoC Limitation`):** All host ports bind strictly to `127.0.0.1` and `sim_internal_net` sets `internal: true` (`postgres` and `rabbitmq` expose zero host ports), without `--privileged` or Docker socket mounts. Adding a non-root `USER` in `Dockerfile` and independent VAPT are tracked under `CAP-05` Pillar 5.
4. **External Free-Tier LLM Data Policy (`Disclosed PoC Limitation`):** `OpenRouterProvider` (`orchestrator/llm_provider.py:343`) sets `"data_collection": "allow"` for `:free` endpoints — safe ONLY for 100%-synthetic redacted PoC payloads; prohibited for real banking telemetry (`CAP-05` Pillar 4).
